Spring Boot + JPA

1. Visão geral da arquitetura

Uma aplicação Spring Boot web é organizada em camadas, cada uma com uma única responsabilidade. O pedido HTTP entra pela borda e desce até o banco; a resposta faz o caminho inverso.

Navegador / Frontend (HTML, React, Next.js) │ HTTP GET /api/pecas/7 ▼ DispatcherServlet ──► HandlerMapping (sistema de rotas) ▼ @RestController → recebe/valida request, devolve DTO + status HTTP ▼ @Service → regras de negócio, @Transactional ▼ @Repository (Spring Data JPA) → consultas sem boilerplate ▼ Hibernate (ORM) ──► JDBC / HikariCP (pool) ──► Banco (MySQL)

Por que camadas?

  • Baixo acoplamento: trocar o banco não altera o controller.
  • Testabilidade: cada camada é testada isoladamente (mocks).
  • Inversão de Controle (IoC): o Spring instancia e injeta os beans.

Estrutura de pacotes típica

2. Spring Boot, IoC e Injeção de Dependência

@SpringBootApplication combina @Configuration, @EnableAutoConfiguration e @ComponentScan. O Spring varre os pacotes, cria os beans (@Component, @Service, @Repository, @RestController) e os conecta.

@SpringBootApplication
public class Application {
  public static void main(String[] args) {
    SpringApplication.run(Application.class, args);
  }
}

Injeção por construtor (recomendada)

@Service
public class PecaService {
  private final PecaRepository repo;
  public PecaService(PecaRepository repo) { this.repo = repo; }
}

Imutável, fácil de testar e não depende de reflexão (@Autowired em campo).

application.yml (conexão com o banco)

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/fashionai
    username: app
    password: ${DB_PASSWORD}
  jpa:
    hibernate.ddl-auto: validate   # nunca "create" em produção
    open-in-view: false
    properties.hibernate.format_sql: true

Segredos vêm de variáveis de ambiente, nunca do código.

3. Entidades JPA e Hibernate

JPA é a especificação (Jakarta Persistence); Hibernate é a implementação padrão. O ORM mapeia classes para tabelas.

@Entity
@Table(name = "peca")
public class Peca {
  @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
  private Long id;

  @Column(nullable = false, length = 120)
  private String nome;

  @Enumerated(EnumType.STRING)
  private Categoria categoria;

  @ManyToOne(fetch = FetchType.LAZY)
  @JoinColumn(name = "marca_id")
  private Marca marca;

  @Version private Long versao;   // lock otimista
}

Relacionamentos

AnotaçãoUsoFetch padrão
@OneToOneUsuário ↔ PerfilEAGER
@ManyToOnePeça → Marca (FK na peça)EAGER
@OneToManyMarca → Peças (mappedBy)LAZY
@ManyToManyPeça ↔ Tag (tabela de junção)LAZY

Boa prática: declare LAZY em tudo e busque o necessário com JOIN FETCH ou @EntityGraph.

Ciclo de vida

transient → managed (persist/find) → detached (fim da sessão) → removed. Entidades managed sofrem dirty checking: alterações são gravadas no flush/commit sem chamar save.

4. Repository (Spring Data JPA)

Você declara uma interface; o Spring gera a implementação em tempo de execução.

public interface PecaRepository extends JpaRepository<Peca, Long> {

  List<Peca> findByCategoria(Categoria c);              // query derivada

  Page<Peca> findByNomeContainingIgnoreCase(String n, Pageable p);

  @Query("select p from Peca p join fetch p.marca where p.id = :id")
  Optional<Peca> buscarComMarca(@Param("id") Long id);   // JPQL

  @Query(value = "select * from peca where preco > ?1", nativeQuery = true)
  List<Peca> caras(BigDecimal min);                      // SQL nativo
}

Hierarquia

Repository → CrudRepository → PagingAndSortingRepository → JpaRepository. Métodos prontos: save, findById, findAll, deleteById, count, existsById.

Problema N+1

Listar 100 peças e acessar peca.getMarca() LAZY gera 1 + 100 consultas. Solução: JOIN FETCH, @EntityGraph ou @BatchSize.

5. Banco de dados e conexões

O Hibernate converte operações em SQL e usa JDBC. O HikariCP mantém um pool de conexões reutilizáveis (abrir conexão por requisição seria caro).

CREATE TABLE marca (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(120) NOT NULL UNIQUE
);
CREATE TABLE peca (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(120) NOT NULL,
  categoria VARCHAR(30) NOT NULL,
  marca_id BIGINT,
  versao BIGINT NOT NULL DEFAULT 0,
  CONSTRAINT fk_peca_marca FOREIGN KEY (marca_id) REFERENCES marca(id)
);
CREATE INDEX idx_peca_categoria ON peca(categoria);

Migrações com Flyway

Em vez de ddl-auto=update, versione o schema em db/migration/V1__criar_tabelas.sql. As versões devem ser únicas; o Hibernate apenas valida (ddl-auto: validate).

Transações (ACID)

Atomicidade, Consistência, Isolamento, Durabilidade. No Spring: @Transactional abre a transação, faz commit no sucesso e rollback em RuntimeException.

6. Service — regras de negócio

É onde vivem as regras, a orquestração de repositórios e as fronteiras transacionais. O controller não deve conhecer o repositório.

@Service
public class PecaService {
  private final PecaRepository repo;
  private final MarcaRepository marcas;
  public PecaService(PecaRepository repo, MarcaRepository marcas){...}

  @Transactional
  public PecaResponse criar(PecaRequest req) {
    Marca m = marcas.findById(req.marcaId())
        .orElseThrow(() -> new RecursoNaoEncontradoException("Marca"));
    Peca p = new Peca(req.nome(), req.categoria(), m);
    return PecaResponse.de(repo.save(p));
  }

  @Transactional(readOnly = true)
  public Page<PecaResponse> listar(Pageable pg) {
    return repo.findAll(pg).map(PecaResponse::de);
  }
}

DTO vs Entidade

Nunca exponha a entidade na API: evita vazamento de campos, loops de serialização e LazyInitializationException. Use record como DTO.

7. Controller e sistema de rotas

@RestController
@RequestMapping("/api/pecas")
public class PecaController {
  private final PecaService service;
  public PecaController(PecaService s){ this.service = s; }

  @GetMapping                       // GET /api/pecas?page=0&size=20
  public Page<PecaResponse> listar(Pageable pg){ return service.listar(pg); }

  @GetMapping("/{id}")              // GET /api/pecas/7
  public PecaResponse buscar(@PathVariable Long id){ return service.buscar(id); }

  @PostMapping @ResponseStatus(HttpStatus.CREATED)
  public PecaResponse criar(@Valid @RequestBody PecaRequest req){ return service.criar(req); }

  @PutMapping("/{id}")    public PecaResponse atualizar(...){...}
  @DeleteMapping("/{id}") @ResponseStatus(HttpStatus.NO_CONTENT)
  public void remover(@PathVariable Long id){ service.remover(id); }
}

Como a rota é resolvida

  1. O DispatcherServlet recebe toda requisição.
  2. O HandlerMapping casa método HTTP + caminho com um método do controller.
  3. Argumentos são resolvidos (@PathVariable, @RequestParam, @RequestBody via Jackson).
  4. O retorno é serializado em JSON (HttpMessageConverter) com o status.
VerboRotaAçãoStatus
GET/api/pecaslistar200
GET/api/pecas/{id}buscar200 / 404
POST/api/pecascriar201 / 400
PUT/api/pecas/{id}atualizar200
DELETE/api/pecas/{id}remover204

Tratamento global de erros

@RestControllerAdvice
class ErroHandler {
  @ExceptionHandler(RecursoNaoEncontradoException.class)
  ResponseEntity<?> nf(RuntimeException e){
    return ResponseEntity.status(404).body(Map.of("erro", e.getMessage()));
  }
}

8. Interface frontend e conexão completa

O frontend (React/Next.js, HTML+JS) consome a API REST por HTTP/JSON.

// frontend
const res = await fetch("/api/pecas?page=0&size=20", {
  headers: { Authorization: "Bearer " + token }
});
if (!res.ok) throw new Error(await res.text());
const pagina = await res.json();   // { content:[...], totalPages, number }

CORS

Se o frontend roda em outra origem, configure WebMvcConfigurer#addCorsMappings permitindo apenas origens conhecidas. Alternativa: proxy/rewrites do Next.js para /api.

Fluxo ponta a ponta (POST /api/pecas)

1. Formulário → fetch POST JSON 2. Filtro de segurança valida JWT (Spring Security) 3. Controller: @Valid (Bean Validation) → 400 se inválido 4. Service: abre transação, aplica regras 5. Repository.save → Hibernate agenda INSERT 6. Commit → INSERT via Hikari → MySQL 7. Service devolve DTO → Controller 201 + JSON 8. Frontend atualiza estado/UI

Rotas do frontend vs backend

As rotas de páginas (ex.: /pecas/[id] no Next.js) são do navegador; as rotas /api/** são do Spring. Não confunda: a página chama a API, e a API nunca renderiza a tela.

9. Boas práticas e testes

  • Controller fino, Service com regra, Repository só com acesso a dados.
  • Use DTOs e Bean Validation (@NotBlank, @Size).
  • Paginação obrigatória em listagens (Pageable).
  • open-in-view: false e fetch = LAZY.
  • Migrações versionadas (Flyway); ddl-auto: validate.
  • Segredos em variáveis de ambiente; consultas parametrizadas (evita SQL injection).
@WebMvcTest(PecaController.class)   // teste de camada web
@DataJpaTest                        // teste do repositório (H2/Testcontainers)
@SpringBootTest                     // integração completa
