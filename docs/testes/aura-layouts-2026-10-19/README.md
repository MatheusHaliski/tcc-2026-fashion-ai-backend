## Validação e dados

- Os relatórios de navegador indicam `SIMULATED` para APIs e `gpuExecuted:false`. MP4s são assets reais do repositório; avatares são modelos genéricos MakeHuman. Não confundir WebGL por software com inferência de IA em GPU.
- Testes Java focados: 26 aprovados, incluindo permissões por XP, Studio, recálculo e inventário Metamorfose (compra, ausência de direito, alteração de configuração, expiração e revogação).
- Na primeira suíte ampla local, 1735 testes passaram e quatro falharam. Dois excederam 5 s enquanto havia renderização por software concorrente; passaram isoladamente. A regressão de câmera foi corrigida (limites da cabine não devem cortar a órbita externa do provador com paredes removíveis). A perda de pedido de tutorial durante hidratação também foi reproduzida no checkout de recuperação e corrigida preservando o pedido até as preferências chegarem. Os registros locais não substituem o CI do commit publicado.
- PDF histórico recuperado de `origin/fix/try-on-lower-piece-3d`: `docs/solicitacoes-conversa-2026-10-19.pdf`. Não foi refeito nem afirmado como salvo no macOS inacessível.

## Caminho real do retrato / GPU

`AvatarPortraitService` → `StylizedPortraitPort` → `AnatomicalTryOnAdapter` (`VTON_WORKER_URL`, `VTON_WORKER_TOKEN`) → `/v1/avatar/portrait` do worker Python. O worker com `VTON_RENDER_PROVIDER=vertex_fashn` chama Vertex por `google_cloud.predict_stylized_portrait`, usando `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`, `VTON_VERTEX_TRYON_ENDPOINT_ID` e `VTON_VERTEX_TRYON_DEDICATED_HOST` conforme configuração existente. Disponibilidade do adapter não prova que o modelo responde. Foto segue no pedido privado, não exige upload manual de cada foto para criar uma imagem Docker. Container/modelo precisam estar efetivamente implantados e inferência validada. Esta verificação não executou FLAME/SMPL-X nem provou fidelidade milimétrica. Não foram alterados secrets ou chaves de criptografia do banco.
